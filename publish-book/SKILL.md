# Publish Review — 发布回检引擎

创作链的**发布环节**。把散在记忆里的"每10章/每卷一轮"节律 formalize 成可执行流程。核心理念:**发布不是终点,是回检点**——每次发布前强制走一轮完整质检,把"写得还行"的自我感觉交给确定性检测。

## 节律:自适应,不死定

- **初值**:每 10 章一轮(沿用既有约定)。
- **动态重算**:与 evolve-style 的 cadence 引擎联动——间隔随作品实际长度调整(短篇密、长篇疏),结构锚点(卷边界)优先触发。
- **每卷更严格**:卷级回检升级检查清单(见 §4),不留"发布后才发现整卷问题"的窗口。

## ⚠️ 铁律:发布目录只收"完成整轮回检"的章节(2026-08-05)

- **事故**:ch21/22 未满 10 章被导出脚本全量导出带进发布目录。
- **根因**:旧导出脚本 glob 全部 manuscripts,无"按轮"概念。
- **现行规则**:
  1. **导出脚本 = 按轮增量**(`~/.claude/skills/build-world/scripts/export_publish.py`,唯一权威):未满一轮的新章导出时文件名带 `(待整轮回检)` 后缀,不进"正式发布";满一轮且发布 txt 标点校验通过 → 自动剥离后缀转正式。
  2. **待整轮回检 ≠ 已发布**:看到 `(待整轮回检)` 后缀的文件,说明该批未满一轮,仍需补完整轮回检(检测→润色→排版→汇总)才能正式发布。
  3. **发布账本**:每批发布记入 `publish-log.md`(ch 范围/字数/检测结果/反思);`publish-log.md` 记录当前批次状态,作为权威进度对照。
  4. **发布前自检**:跑导出脚本后,确认"已正式发布"章数与账本一致;"待整轮回检"若非空且未满批次,勿当正式发布。

## 五步流程(强制闭环)

```
检测 → 润色 → 排版 → 发布 → 汇总反思
```

### 1. 检测(确定性优先,免费)

| 检测项 | 工具 | 通过标准 |
|---|---|---|
| 标点规范化 | `normalize_punct.py --all` | 半角→全角,`「」`→`“”` |
| 引号规范(GB/T 15834) | `check_punct_spec.py --all` | 嵌套/独立对话/省略号全规范 |
| 引号规范(发布txt) | `check_punct_spec.py <发布目录> --all` | 发布目录为嵌套结构(发布/卷一/xxx.txt),**必须用 --all 递归**;不加 --all 会提示子目录 |
| AI 味 | `detect_aislop.py` + `non_human_scan.py` | 命中不显著,或已改写 |
| 重复描写 | `repetition_detect.py` | 无句子级重复 |
| 常识合理性 | `commonsense_check.py` | 特殊题材豁免后无违常识 |
| 套路 | `cliche_detect.py` | 无套路堆积,或有反套路 |
| 一致性 | write-chapter 连续性校验 | 无死人复活/伏笔悬置过久/POV越界 |

### 2. 润色(remove-ai-tone 两遍式)

- 第一遍:逐段扫 7 类 AI 模式 + AI 身份指纹 + 非人感结构。
- 第二遍:AI 自审"这段哪里还明显 AI 生成",列 3-5 条针对性再改。
- **每卷更严格**:加格式控制(长短段/留白/排版)+ 白金手法抽查(≥2 类)。

### 3. 排版

- `normalize_punct.py --all` 扫全书(防漏,教训:以前只扫眼前几个漏了 ch005)。
- `export_publish.py <项目目录>` 导出"分卷文件夹 → 章 txt"发布格式(**按轮增量**,见上方铁律;唯一权威脚本,勿再用项目旧 `export_publish_adapted.py`)。
- 检查:段落长短、留白、分章完整性、文件名规范。
- **txt 正文必须带章节名**(章标题保留为正文首行,export_publish.py 已实现;抽查第一行=文件名对应章节名)。

### 4. 发布

- 导出产物确认、章节顺序、封面/简介(若有)。
- **确认导出结果**:"已正式发布"章数应与账本一致;"待整轮回检"若非空且未满一轮,该批**不视为已发布**(见上方铁律)。
- 记录发布批次(ch 范围、字数、时间)进 `publish-log.md`。

### 5. 汇总反思(喂回进化链)

- 本批发布质量总结:哪些检测项连续通过/连续失败。
- 读者反馈(若有)按 apply-feedback 分级接续。
- 手法得失、发布问题沉淀进 `lessons.md` + `publish-log.md`。
- **节律重算**:根据本批实际长度 + 读者反应,重算下轮发布间隔。

## 发布账本(publish-log.md)

```
## 批次4(2026-08-04, ch31-40)
- 字数: ~32000
- 检测:标点通过/引号2处修复/AI味1段改写/常识通过
- 读者反馈:节奏偏慢(3条C级)→ 已接 apply-feedback
- 下轮间隔:重算为12章(篇幅变长)
```

## 边界

- 本引擎管"发布前质检 + 发布后反思",**不管内容创作**(那是 write-chapter)。
- 检测和润色工具来自 remove-ai-tone / plan-plot,本引擎只是调度。
- 与 evolve-style 的关系:发布汇总反思是它的"信号源"之一;节律与其 cadence 联动。

## 喂给谁 / handoff

- **remove-ai-tone**:检测+润色工具源。
- **plan-plot**:常识/套路检测源。
- **write-chapter**:一致性校验 + 发布批次记录。
- **apply-feedback**:发布后读者反馈分级接续。
- **evolve-style**:节律联动 + 汇总反思进进化。
- **write-novel**:发布需求路由到本 skill。
- 产物:`<项目目录>/publish-log.md`(发布账本)+ 导出发布目录。

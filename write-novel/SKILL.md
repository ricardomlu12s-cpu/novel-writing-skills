# 创作工作链条(Creative Work Chain)

小说创作链的**编排枢纽**。你只管说创作需求,它决定走链上哪一环、产出喂给谁。

## 项目激活机制(开书后链不可关闭)

**一旦开始创作,本链对当前项目始终生效,不得关闭。**

- **开书激活**:说"开始创作《书名》"或 `/开书《书名》` → 写激活标记 `<项目目录>/ACTIVE` + 更新记忆 `active-novel-project` → 链进入"持续创作"状态。
- **开书登记类型(原创/同人·四档)**:开书时**必须**登记项目类型:
  - `原创` → 走原链(learn-style → build-world → write-chapter)。**可选拆书**:想深度学一部作品(结构/伏笔/世界观骨架),可先 study-book 拆作"学习参考"(非基准线,不守恒);只想学文风则 learn-style 够用。
  - `同人` → 额外登记:主书(源作)、源作文本路径、`source-canon/` 位置,写进 `active-novel-project` 记忆 + `source-canon/manifest.json`。**并定同人四档之一**(决定拆书深度 + 守恒强度):补白型→强守恒 / 改写型→守恒世界观 / 架空型→弱守恒 / 融合型→主从底盘。
  - 同人项目新会话自动装配:按档位装配源作基准(source-canon)+ 守恒层级 + OOC 红线 + 蝴蝶效应账本(补白/改写型全量,架空型只浅层元素)。
- **会话自动恢复**:活动项目写进**始终加载的记忆**(active-novel-project,只存稳定事实),每次新会话自动知道"该续写哪本"。
  - **进度权威源(2026-08-04 教训)**: 记忆**不存章节级进度**——进度是磁盘上持续变化的数据,快照必然滞后(实发: 记忆停在第1章,实际已写10章)。查"写到哪里了"一律按: **①交接摘要顶部最新进度节 → ②列 `drafts/` 实际文件(文件数=实际进度)→ ③该章细纲 + `summaries/L1/` → ④刷新面板看创作意见**。记忆与磁盘不一致时,以磁盘+交接摘要为准。
  - 新会话自动装配项目状态(分层摘要+正典账本+设定库+面板),**不重新触发、不断链**。
- **会话交接(完整继承历史细节)**:每次会话结束/重开前,执行**交接协议**——把本会话新增的决策史/方法论/技术坑/待办/**进度**追加到 `<项目目录>/交接摘要.md`(不覆盖旧内容);记忆**只更新稳定事实,不写进度**。新会话读记忆+交接摘要+产物三轨,继承的信息量与最初会话一致。**详见 `references/session-handoff.md`**。
- **不可关闭**:项目激活期间,链不因会话结束/新会话而中断;`/cancelomc` 只停当前单次操作,不解除项目激活。
- **唯一解除**:显式说"完结《书名》"/"结束这个项目" → 移除 ACTIVE 标记 + 清记忆(全书完结或暂停)。
- **数据持久**:正文/摘要/账本永久存 `<项目目录>/`,跨会话、跨电脑都存活。

## 链路图(小说创作链)

```
study-book ──源作设定库──▶ learn-style ──风格指纹──▶ build-world ──设定/伏笔──▶ write-chapter ──草稿──▶ remove-ai-tone ──▶ 定稿
  (同人:必拆·立基准)            (学习文风/角色/情节)       (世界观/角色卡/面板)      (分层摘要+正典账本)   (中文去AI味)
  (原创:可选拆·学参考)
        │                              │                      │                        │
        └──────────── write-novel(创作链枢纽,路由+全链手册) ────────────────────┘
                                   │
  场景/质量 skill(在 write-chapter 质量门内按需嵌调):
     plan-plot(情节/高潮/战斗) · adapt-platform(平台/群像) · write-romance(感情线)
     write-mystery(智斗) · apply-feedback(读者意见微调)
                                   │
  横切 skill:
     token-ops(降本·批量/缓存) · evolve-style(进化·节律/双轨指纹/防固化)
     publish-book(发布回检·检测/润色/排版/发布/反思)
```

> **同人文**:走 study-book 入口,**必拆书**先立源作设定库(`<项目目录>/source-canon/`)作基准线,再走 learn-style→build-world→write-chapter。**原创**:**可选拆书**——想深度学一部作品(结构/伏笔/世界观)就拆(产物作学习参考,不守恒);否则跳过拆书,直接 learn-style 及之后。

## 路由表(大白话 → 走哪一环)

| 用户可能说 | 走链上哪一环 |
|---|---|
| "学习这个作品的文风"/"吸收这本书的风格"/"仿写但别照搬" | learn-style |
| "写同人文"/"拆书"/"解构"/"伏笔挖掘"/"原作设定"/"深度拆解" | **study-book**(同人=必拆立基准;原创想深学一部作品=可选拆作参考) |
| "建世界观"/"写角色卡"/"看创作面板"/"故事数据"/"伏笔状态"/"战力崩了" | build-world(面板;战力数值校验也在这里) |
| "写第X章"/"续写"/"长篇创作"/"连续写" | write-chapter(项目已激活时;未激活先经本枢纽三轨装配) |
| "去AI味"/"这不像人写的"/"润色" | remove-ai-tone |
| "情节老套"/"高潮安排"/"不合常识"/"读者共鸣"/"分卷"/"卡文"/"写不下去" | plan-plot |
| "读者意见"/"这章读者说"/"微调"/"按读者建议改" | apply-feedback |
| "智斗"/"推理"/"线索"/"博弈"/"智商对决" | write-mystery |
| "平台适配"/"起点风"/"番茄风"/"群像"/"势力成长" | adapt-platform |
| "感情线"/"CP"/"感情戏"/"爱情线" | write-romance |
| "角色脸谱化"/"对话都一样"/"这场戏没推进"/"反转太突兀" | build-world(角色/对话)或 plan-plot(因果/反转) |
| "卡文了" | plan-plot(卡文处理/决策树) |
| 模糊创作任务、不知道归谁 | **本枢纽**判断 → 派发 |
| "重开会话"/"换会话"/"太长了吧"/"会丢失吗"/"交接一下"/"开新会话" | **会话交接协议**(执行交接:追加交接摘要+更新记忆,保证新会话完整继承) |
| "太烧 token" | token-ops(横切) |
| "该总结了"/"该学习了"/"我的风格"/"进步了吗"/"下一卷写什么改进"/"风格漂移" | evolve-style(横切进化) |
| "发布"/"发表"/"上架"/"排版"/"回检"/"检查一遍" | publish-book(发布回检) |
| "我记得这个方法在 references/记忆里有" | memory-dedup-map(查唯一载体,防记忆/references 两处漂移) |
| "两个约束打架了"/"这里爽点和人设冲突"/"该听谁的" | **decision-priority**(裁决优先级:不牺牲 P1-P8 换爽点,见 references/decision-priority.md) |

## 触发词消歧表(易混词 → 走哪一环)

| 易混词 | 走哪一环 | 判定 |
|---|---|---|
| **排版** | publish-book(发布整页/标点规范) | 发布场景;若单指"段落太长/格式",走 remove-ai-tone |
| **润色** | remove-ai-tone(去AI味) | apply-feedback 的微调也会润色,但入口是读者意见 |
| **微调** | apply-feedback(创作链) | 指改小说章节;若指"微调训练模型"= ml-finetune(技术链) |
| **手法** | evolve-style(能力画像/待练) | 若指"白金手法/战斗手法"走 plan-plot |
| **写小说/开始写** | write-novel(枢纽,先建链再分配) | 不直接触发 write-chapter,先经枢纽登记 |
| **该学习了/总结** | evolve-style(进化节律) | 不是 apply-feedback 的微调,也不是 plan-plot 的高潮复盘 |
| **进化/我的风格/风格漂移** | evolve-style(双轨指纹/防固化) | 不是 learn-style 的吸收,是已写作品风格的演进 |
| **战力崩了** | build-world(战力数值校验/跳级/成长曲线) | 指数值失衡/跳级/越级;若指"打斗场面不好看"才走 plan-plot |
| **续写/写第X章** | 项目已激活→write-chapter;未激活→先本枢纽三轨装配 | 新书不能从 write-chapter 直接起(会缺同人 source-canon 登记) |

## 全链运行手册(一部新小说的流程)

1. **开书准备**:确认题材/风格/目标读者。**登记类型(原创/同人)+ 主书 + 源作路径**。**选平台 → adapt-platform 注入参数**(起点/番茄)。**若写同人文 → 先 study-book 拆书立源作基准**。若要借鉴某作品手法 → learn-style 提风格指纹。
2. **建设定**:build-world 建世界观/角色卡/伏笔注册表 → 渲染创作数据面板,你查看修改。
3. **写正文**:write-chapter 装配活跃实体 → 每章走分章质量门(记忆同步/一致性/风格/正文/门禁/进化判定等 9 步,详见 write-chapter)。
   - **写必落盘纪律**:说"写/正在写"**必须配工具落盘**(Write 到 drafts/),禁止只口头声明进度;每章写完用 Bash 确认文件存在,不能"应该写好了"。
4. **去AI味**:remove-ai-tone 审查每章草稿,通过才进定稿。
5. **看面板+意见**:写后刷新创作数据面板,查看故事数据/伏笔状态/创作意见,调整后再续写。
6. **降本**:批量章节生成走 token-ops(低上下文策略 + Batch/缓存)。

## 边界
- 创作链聚焦**小说创作**(文字)。后续改编链(动态漫画解说)是独立计划,等创作完这部小说再启动。
- 每环完整步骤见各自 skill;本枢纽只串链,不重复技术细节。

## 喂给谁 / handoff
- 全部指向小说创作链五环(learn-style/build-world/write-chapter/remove-ai-tone)。
- 与 pipeline(六领域链)并行:创作链是"内容生产",工作链是"技术/安全/训练"。

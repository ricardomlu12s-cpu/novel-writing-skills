# 会话交接协议(Session Handoff Protocol)

创作链的**跨会话连续性保障机制**。保证: **无论交接多少次,所有历史细节和交接摘要都不遗漏,新会话继承的信息量与最初会话一致**。

## 核心铁律

> **每条历史细节只在一个地方完整保存,其余地方只存指针/摘要。**
> 交接 = 指针链的逐代追加,不是覆盖重写。

### 铁律二:记忆不存"进度",进度以磁盘权威源为准(2026-08-04 教训)

> **`active-novel-project` 记忆快照只存稳定事实**(书名/类型/路径/约束/方向),**绝不存章节级进度**。
> 章节级进度 = 已写章节/字数/下一章/伏笔状态,是**磁盘上持续变化的数据**,每次会话结束时人工同步记忆快照必然滞后。教训: 某次会话结束后记忆停在"第一章",实际已写到第十章,新会话被误导(2026-08-04 实发)。

**进度权威源优先级(新会话续写固定路径)**:
1. `交接摘要.md` 顶部最新「进度」节(含已写章节清单/下一章)→ 2. 列 `drafts/` 实际文件(文件数=实际进度)→ 3. 该章细纲条目 + `summaries/L1/` 冻结摘要 → 4. 刷新 `panel/` 看创作意见。
**若记忆与磁盘不一致 → 一律以磁盘 + 交接摘要为准**,记忆只更新登记行的稳定事实,不复制进度。

**进化状态装配(evolve-style)**:新会话启动时一并读取进化三件——`cadence.jsonl`(节律账本,知"现在该不该学")+ `evolution/fingerprint-actual.md`(实际指纹)+ `evolution/capability.md`(能力画像)。交接摘要尾部追加"进化状态"节(最近学习层级/待练手法/锁死区告警),保证跨会话进化不中断。

### 为什么必须"追加不覆盖"
- 会话 A 产生决策 X,写进交接摘要。
- 会话 B 继承后产生决策 Y,若**覆盖**摘要,则 X 的"为什么"丢失。
- 追加则 X→Y→Z 逐代累积,任何一代会话都能回溯完整决策链。

## 一、三轨存储架构(历史细节的存放)

| 轨 | 内容 | 位置 | 更新方式 |
|---|---|---|---|
| **① 始终加载记忆** | 项目**稳定事实**(书名/类型/路径/方向/约束) | `~/.claude/projects/.../memory/active-novel-project.md` | **覆盖**(只存稳定事实,**不存章节级进度**) |
| **② 正典产物** | 设定库/大纲/账本/角色卡(拆书+重排+写作产物) | `<项目目录>/` | **追加**(产物本身累积,含全部版本) |
| **③ 交接摘要** | 决策史/方法论/技术坑/待办/未决 + **进度节**(已写章节清单/下一章) | `<项目目录>/交接摘要.md` | **追加**(每次会话追加一节,不覆盖) |

**关键**: ① 是"当前在哪的稳定指针",② 是"世界长什么样"的产物,③ 是"为什么这么定"的决策史 + **进度记录处**。三者合起来 = 完整继承。新会话三轨全读,信息量 = 最初会话。

> **进度放哪**: 已写章节/下一章/伏笔状态**只记在交接摘要③(进度节)+ 磁盘(drafts/summaries/foreshadowing/面板)**。记忆①不复制进度。查"写到哪里了" = 读交接摘要③顶部 + 列 drafts/ 实际文件。

## 二、交接时机(何时触发)

**每次会话结束/重开前,必须执行交接**(不限于用户主动要求):

- **常规交接**: 用户说"重开会话/太长/换会话" → 执行交接。
- **阶段交接**: 完成一个大阶段(拆书/重排/风格吸收/设定/卷写完)→ 执行交接。
- **断点交接**: write-chapter 的 token-budget-guard 触发"开新会话" → 执行交接(正文断点已由 checkpoint 处理,此处交接创作链上下文)。
- **强制交接**: 检测到上下文接近极限/会话异常 → 执行交接。

## 三、交接执行流程(新会话启动时 + 会话结束时)

### A. 会话结束时(写交接摘要)

1. **盘点本会话新增的历史细节**(新会话无法从记忆/产物自动继承的):
   - 方向决策/拍板史(用户说了什么、为什么这么定)
   - 方法论/原则(重排/写作的新约定)
   - 技术坑与解决(编码/JSON/权限/工具劫持等)
   - 待办/悬而未决事项
   - 下一步建议
2. **追加到交接摘要**: 读现有 `交接摘要.md` → **在末尾追加新一节**(标会话代次/日期),不覆盖旧内容。若不存在则新建。**本节含「进度」子节**(本会话已写章节/字数/下一章计划)。
3. **更新记忆**: `active-novel-project.md` 覆盖为当前快照(**只覆盖稳定事实**: 书名/类型/路径/方向/约束;若本会话新增了约束或方向变更才更新对应行,**绝不写章节级进度**,进度已写在交接摘要③)。并加"交接摘要位置"指针。
4. **更新 ACTIVE 标记**: 确认 `<项目目录>/ACTIVE` 存在。

### B. 新会话启动时(读交接摘要)

1. **读记忆** → 自动装配项目**稳定事实**(当前在哪本书/路径/约束)。
2. **读交接摘要** → 完整继承决策史/方法论/技术坑/待办 + **顶部最新进度节**(已写章节清单/下一章)。
3. **列磁盘实际文件**(`drafts/`/`manuscripts/`/`summaries/L1/`)→ 以文件数为准确认实际进度,**不信记忆/旧计数**。
4. **读正典产物**(按需)→ 设定库/大纲/账本。
5. **自检(checklist)**: 确认无遗漏(见下)。

---

## 四、交接摘要的标准结构(每节必含)

新会话读摘要,应能回答"最初会话知道的一切"。摘要每节(每次交接追加)固定结构:

```
## 交接 N(2026-XX-XX, 会话 [标题/主题])
### 本阶段做了什么
### 方向决策(新增/变更)
### 方法论(新增约定)
### 技术坑与解决
### 待办/悬而未决
### 下一步建议
### 进化状态(evolve-style)
- 最近学习: 第X章 L3 层(触发: 弧闭合)
- 待练手法: 群像POV / 对话密度
- 锁死区/失控区告警: 无 / 修辞偏差高
```

摘要头部固定放**总目录/索引**(各次交接的一行摘要),新会话扫一眼即知全部交接史。

---

## 五、可核验的完整性自检(新会话启动必做)

新会话读完全部三轨后,核对:

- [ ] 项目当前在哪(记忆稳定事实 + **交接摘要进度节**)已知
- [ ] **记忆进度 vs 磁盘实际文件一致**(若记忆滞后,以磁盘+交接摘要为准,更新记忆仅稳定事实)
- [ ] 方向/雷区/文化守恒已知(记忆+方向基准)
- [ ] 全部交接史读过(摘要总目录 = 本次数)
- [ ] 关键产物位置已知(source-canon/大纲/账本)
- [ ] 待办/未决事项已知
- [ ] **确认无"会话独有的知识"被遗漏**——若有,回原产物找,不臆造

> 铁律: 新会话永远不要假设"旧会话的想法我猜得到"。所有决策都要有**书面依据**(记忆/摘要/产物),否则回读原文再定。

## 六、多代交接示例

```
会话1(拆书): 交接摘要.md 第1节(拆书决策/编码坑/分章off-by-one)
  → 会话2(重排): 追加第2节(重排原则/7卷大纲决策),不覆盖第1节
    → 会话3(风格吸收): 追加第3节(文风指纹/吸收规避),第1、2节仍在
      → 会话4(写正文): 追加第4节(...)  ← 读摘要 = 1+2+3+4 全知道
```

**第 N 代会话读摘要,永远读到 N 代全部决策史,不遗漏最初。**

---

## 七、与现有机制的关系

- **write-chapter checkpoint.md**: 管"正文写到哪"的断点。交接摘要管"创作链上下文到哪"。两者互补,不重复。
- **memory active-novel-project**: 管"稳定事实"(覆盖,不存进度)。交接摘要管"完整决策史 + 进度"(追加)。两者互补。
- **build-world 设定库/伏笔**: 正典产物,追加累积。交接摘要给这些产物**加索引和上下文**(为什么这么设计)。

---

## 八、触发词

用户说"重开会话"/"换会话"/"太长了吧"/"会丢失吗"/"交接一下"/"开新会话",或进入新大阶段,均触发本协议。

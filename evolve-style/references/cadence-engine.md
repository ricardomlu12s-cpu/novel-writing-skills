# 节律引擎(Cadence Engine)

创作进化引擎的**节拍器**。决定"现在该不该学习、学哪层、为什么"。三尺度自适应,不死定章节数。

## 触发优先级(取最早)

```
结构锚点 > 信号阈值 > 间隔兜底
```

三者任一命中即触发对应层级;同一时刻多命中 → 取最高层级,并把其余原因记入 cadence.jsonl。

## 维度一:篇幅尺度(定粒度)

| 档位 | 预计总章数 N | 小学习间隔 | 中学习间隔 | 大学习 |
|---|---|---|---|---|
| 短篇 | ≤40 | max(3, N/12) | max(10, N/4) | 全书 1 次 |
| 中篇 | 41–100 | max(4, N/12) | max(12, N/5) | 每卷 + 全书 |
| 长篇 | 101–300 | max(6, N/12) | max(20, N/6) | 每卷 + 全书 |
| 超长篇 | 301+ | max(8, N/12) | max(30, N/7) | 每卷 + 全书 |

### N 的估算与动态重算

**估算方式(取两者孰高)**:
- **上推**:总纲卷弧数 × 每弧预计章数。
- **外推**:已写章数 ÷ 细纲覆盖率(已用细纲数 / 总细纲数)。

**重算时机**:每次学习后,按**作品实际长度**重算。实际更慢 → N 变大 → 间隔变宽;实际更快 → 收窄。**数字永远跟着作品长,不跟日历。**

### 示例(某同人项目,已写 20 章)

细纲覆盖 20/40 → N 外推 = 20 ÷ 0.5 = 40 → **短篇档**:
- 小学习间隔 = max(3, 40/12) = max(3, 3.3) = **4 章**
- 中学习间隔 = max(10, 40/4) = **10 章**
- 大学习 = 全书 1 次(完结时)

写到第 30 章时若细纲显示总长其实 80 → 重算为**中篇档**,间隔自适应变宽。

## 维度二:结构尺度(定锚点,优先于一切)

总纲细纲在,就不用猜间隔——结构节点就是硬锚点。

| 结构锚点 | 触发层级 | 依据 |
|---|---|---|
| 卷边界 | 大学习(L4) | 总纲 `plan.md` |
| 剧情弧闭合 | 中学习(L3) | 细纲弧边界 |
| 情节节点闭合(因果链走完) | 小学习(L2) | 细纲 `chapter-outlines/` 情节单元 |
| 地图/题材/时间跳跃 | 强制风格校准 | 最易漂移点 |
| 新角色批量登场(≥3) | 声线/对话密度校准 | 角色卡 |
| 状态机联动缺失告警 | 中学习(L3) | plan-plot |

## 维度三:信号尺度(定触发,非计划内)

| 信号 | 阈值 | 触发 |
|---|---|---|
| 风格漂移 | 检测超阈值 | 立即小学习 + 指纹核对 |
| AI 味命中率 | 连续 2 章高 | 小学习 + remove-ai-tone 加强 |
| 质量门同类问题 | 连续 3 章同一类 | 中学习(查系统问题) |
| 读者反馈 C 级 | ≥3 条指向同一维度 | 中学习 |
| lessons 注入失效 | 连续 N 章重犯旧错 | 深度复盘,标记该条降级/重写 |

## cadence.jsonl(节律账本,append-only)

字段(以 `cadence_calc.py` 实际产出为准):

```
{"ch":20,"type":"learn","level":"L4","trigger":"arc_closed","n_est":40,"ts":"auto"}
{"ch":21,"type":"check","level":null,"trigger":"chapter_done","n_est":41,"ts":"auto"}
{"ch":22,"type":"learn","level":"L4","trigger":"arc_closed","n_est":42,"ts":"auto","decision":"句长16.5升级为作者指纹(作者裁决)"}
```

- `type`: `learn`(触发学习)或 `check`(仅登记未触发)。
- `trigger`: `arc_closed`(弧/卷闭合·结构锚点)/ `small_interval` / `mid_interval`(间隔兜底)/ 信号名(如 `lessons_injection_stale`);`type=check` 时记 `chapter_done`。
- `level`: 触发学习的层级(L2/L3/L4),未触发为 null。
- `n_est`: 本次估算总长。
- `ts`: 固定 `"auto"`(脚本产)。
- `decision`: **可选**,作者裁决时手工追加(如指纹升级结论)。

- **只追加,不改、不删历史**(与伏笔/承诺状态机同一套逻辑)。
- 每章后必登记一次(type=check 或 learn),系统读账本即知"现在该不该学",**不依赖模型自觉**。
- 状态机定义同步进 `write-novel/references/state-machine-map.md`。

## 自动化程度(边界)

- **采集/检测/登记**:由 **write-chapter 写一章的流水线 step 7.6 触发**(写第X章时自动执行,无需作者额外提醒),**非 Stop hook 全自动**。理由(2026-08-13 决策):曾设计 `cadence_hook.py` 挂 settings.json Stop hook 全自动采集,但 hook 未接线、状态停在 23 章(实际已 33 章),"全自动"名存实亡;改为写章流程内置,时机正确、可控、无 hook 失败风险。
- **间隔重算**:脚本自动算,作者不参与。
- **触发执行**:触发即跑对应层级(由 write-chapter 在定稿后执行)。
- **重量注入(指纹升级/风格重定向/能力画像)**:自动生成决策,**作者确认后生效**。

> `cadence_hook.py` 保留但**不默认接线**;如未来要接 Stop hook,先在 settings.json 验证幂等后再启用。

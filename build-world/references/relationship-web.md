# 多维关系 + 冲突网(Relationship Web + Conflict Web)

**问题**:现有关系账本 `relationships.jsonl` 只有「敌对→结盟→对立」三态,不足以表达真实人物的复杂关系——"喜欢但不信任""讨厌却尊重""信任却因职责对立"。三态会把人物写扁。借鉴《龙族人生模拟器》的多维关系,落到通用创作。

## 1. 多维关系(替代单一好感度)

**禁止**用单一"好感度"衡量关系。至少维护这些维度:

| 维度 | 含义 | 例 |
|---|---|---|
| 熟悉 Familiarity | 认识多深 | 点头之交 vs 生死之交 |
| 信任 Trust | 是否信对方说的话/不会害自己 | 信任≠喜欢 |
| 尊重 Respect | 是否认可对方的能力/为人 | 讨厌但尊重 |
| 好感 Affinity | 情感上的亲近 | 喜欢≠信任 |
| 戒备 Suspicion | 是否提防 | 爱但有戒心 |
| 利益一致 Interest | 目标是否一致 | 利益一致但随时退出 |
| 依赖 Dependence | 一方是否离不开另一方 | 依赖≠爱 |
| 责任 Duty | 因职责/身份产生的义务 | 责任凌驾于情感 |
| 秘密共享 Secret Bond | 共享秘密的羁绊 | 知道同一个秘密 |
| 人情 Debt | 欠了人情/恩情 | 恩情≠好感 |
| 冲突 Conflict | 当前的矛盾点 | 冲突≠敌对 |

**核心**:这些维度可以**互相矛盾地共存**:
- 喜欢但不信任(角色 A 对 B)
- 讨厌却尊重(强者之间的敬意)
- 信任却因职责对立(两个阵营的好友)
- 利益一致但随时准备退出合作

**界面展示**:普通界面只显示自然标签(如"老友""宿敌""亦敌亦友"),不显示全部隐藏数值——但写作时这些维度要在心里/账本里。

### 落地
- `relationships.jsonl` 从三态扩展为多维字段(每对关系一条,含 11 维的状态 + 一句"当前关系标签")。
- 关系突变须有动机(不突然翻转),且**逐维更新**(信任降了,尊重可能还在)。

## 2. 冲突网(替代二元阵营)

**禁止**把重要剧情写成"正派 vs 反派"。核心矛盾优先设计成**冲突网**,一个人物可同时处在多组矛盾中。

典型矛盾(通用):
```
个人愿望 vs 责任
家族 vs 自由
身份 vs 真实自我
朋友 vs 组织命令
真相 vs 保护某人
复仇 vs 未来
权力 vs 人性
生存 vs 原则
私人关系 vs 阵营利益
```

- 一个人物可以同时处在 **3—5 组矛盾**之中。
- 反派也要有"他为什么这么做"的合理内核(不是纯恶)。
- 阵营不是铁板一块(见下)。

## 3. 组织/势力不是一个人(去铁板化)

- "获得某组织信任" ≠ 组织里每个人都信任主角。
- 组织内部可以有**派系**,不同派系对主角态度**同时矛盾**:
  - 学院觉得主角有价值;执行部觉得主角适合任务;校董觉得主角危险;某教授觉得主角不稳定。
- **内部意见**、**玩家/主角的价值 vs 威胁** 分开记。

### 落地
- 势力系统(adapt-platform 的 faction-growth / build-world 势力)加"内部派系 + 对主角的分歧态度"。
- 写作时,大组织的态度不是单数,而是"组织里谁怎么看"。

## 4. 与现有机制的接缝(不重复)

| 已有 | 本机制补什么 |
|---|---|
| relationships.jsonl(三态) | 升维到 11 维,表达"矛盾共存" |
| write-romance(CP 合理性) | CP 是关系的一个特例(爱情),本机制管所有关系(友情/亲情/师徒/竞争/忠诚/敌对/政治) |
| ensemble-cast(群像) | 群像管"谁在场",本机制管"他们之间是什么关系" |
| supporting-cast(配角安排) | 配角安排管"戏份",本机制管"配角与主角/彼此的关系质地" |

## 5. 检查清单(每卷/关键关系节点)

- [ ] 这段关系是"单一好感度"吗?(→ 升级为多维,找矛盾点)
- [ ] 有"喜欢但不信任/讨厌却尊重"这类立体关系吗?
- [ ] 冲突是二元正反派吗?(→ 改成冲突网,一人多组矛盾)
- [ ] 大组织是铁板一块吗?(→ 拆成派系,态度分歧)
- [ ] 关系突变有动机吗?(→ 逐维更新,不突然翻转)

# 伏笔账本分治表(源作 vs 同人)

**问题**:同人项目里源作伏笔和同人伏笔混在一起,无法区分"哪条是原作就有的(只读)、哪条是自己埋的(可追加)"。两套账本需要分治,否则防OOC/防设定冲突检查会误判。

## 分治原则

- **源作伏笔 = 不可变基准线**,只读,防OOC红线的依据。
- **同人伏笔 = 可追加可流转**,自己的创作空间,防"挖坑不填"。
- **两套分开存,桥接显式登记**——源作伏笔不改,但可以"被同人剧情回收/呼应"。

## 目录归属

```
<项目目录>/
├── source-canon/foreshadowing.jsonl   # 源作伏笔(只读,拆书产物)
└── foreshadowing.jsonl                # 同人伏笔(可追加,build-world 管)
```

## 两条桥接规则

1. **回收引用**:同人伏笔回收源作伏笔 → 源作伏笔的 `payoff_ch` 不改,**记在同人侧**:`{"type":"bridge","src":"源作f002","to":"同人f003","ch":58}`。
2. **改写级联**:同人剧情重排导致源作伏笔"失效" → **不改源作账本**,在 `butterfly-ledger.jsonl` 记一条(改锚点→重排下游→兑现)。

## 桥接状态机

```
源作伏笔:只读,永不流转
同人伏笔:规划中(未来卷,未开启)→ 开启 → 悬置 → 回收 / 桥接源作伏笔 / 遗忘(告警)
```

**分层语义**:同人伏笔按 `opened_ch` 是否 ≤ 当前进度分两态:
- **已开启**(数字章号 ≤ 已写进度):`status` 用 开启/悬置/回收,参与悬置告警。
- **规划中**(卷X 或 数字章号 > 已写进度):`status=规划中`,未来卷未开启,**不参与悬置告警**。
- 伏笔登记时:已写到的埋数字章号,未写到的标"卷X"并 `phase=规划中`;写到该章时再转"已开启"。

## 面板显示

创作数据面板分两栏:**「源作伏笔(只读基准)」** + **「同人伏笔(创作区)」**,桥接条目标注 `↔ 桥接源作 f002`。

## 校验联动

- write-chapter 连续性校验:同人伏笔查"悬置过久/遗忘";源作伏笔查"同人是否让角色用了未回收源作伏笔的信息"(POV 越界)。
- study-book:源作伏笔由拆书生成,后续只读,不回流。

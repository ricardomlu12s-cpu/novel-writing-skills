# 分层摘要冻结(Hierarchical Summary Freezing)

借鉴 write-chapter-writer 的六层摘要冻结方案。核心:**每层摘要写定即"冻结",防止"传话游戏"稀释早期细节**。

## 层级结构
```
L0 正文        manuscripts/ch001.md(原文,永久保留)
L1 单章摘要     summaries/L1/ch001.md   每章写完立即生成
L2 区块摘要     summaries/L2/block01.md 每5章合并
L3 篇章摘要     summaries/L3/arc01.md   一个剧情弧(约一卷)
L4 卷摘要       summaries/L4/vol01.md   一卷
L5 全书摘要     summaries/L5/novel.md   全书顶层
```

## 冻结规则
- **每个 L 层写定即冻结**,不再改动。早期细节不会被后续章节"重写"掉。
- 新章节写前**只注入**:
  ```
  L5 全书摘要 + 当前卷 L4 + 当前弧 L3 + 最近区块 L2
  ```
  而非全量正文(低上下文策略,省 token)。

## 生成时机
- L1:每章写完立即生成(依赖 L0)。
- L2:每5章合并一次(依赖 L1 1-5)。
- L3:每弧结束(依赖 L2)。
- L4:每卷结束(依赖 L3)。
- L5:全书里程碑时(依赖 L4)。

## 摘要内容要点
- **事实优先**:人物当前状态、关系变化、关键事件,不写修饰。
- **可检索**:摘要与正典账本 facts.jsonl 对齐(同一事实两处都能查到)。
- **防稀释**:L1 是最细粒度,后面层级只"压缩"不"改写"早期事实。

## 与正典账本的关系
- 摘要 = 叙事层记忆(给模型看)。
- 正典账本 facts/promises/timeline = 校验层记忆(给检查用)。
- 两层都只追加,是"几百章不崩"的双保险。

# Token 预算守卫(检测→询问→落盘→续写)

检测到下一章预计消耗巨额 token 时,自动询问是否开新会话;同意则落盘断点、给出续写指引。**体验上是"自动开新会话",实际是"检测+询问+落盘+无缝续"闭环。**

## 诚实边界
无法真正在终端 spawn 新交互会话(那是启动层)。但"检测→询问→落盘断点→新会话无缝接"等价实现目标。

## 检测逻辑(每写 N 章后检查)
1. **累计用量**:本会话已写入的 token 量(可用 `/usage` 或对话上下文估计)。
2. **预计下章注入量**:分层摘要(L5+L4+L3+L2)+ 活跃实体 + RAG 回读 + lessons,固定大小,可估算。
   - **确定性估算**(新):跑 `context_budget.py`,直接算出下一章注入哪些文件、各多少 token、大头在哪:
     ```bash
     python3 ~/.claude/skills/write-chapter/scripts/context_budget.py estimate <项目目录>
     ```
     输出按项列出(L4/L3摘要、角色卡、伏笔、关系、lessons、RAG 等),一眼看出 token 花在哪。
3. **触发阈值**:满足任一 → 触发询问:
   - 累计对话上下文 > 会话预算的 70%(如 200k 窗 → >140k)。
   - 单章生成历史已超过 X 章(经验值 10-20 章)。
   - 对话明显变卡/响应变慢。

## 触发流程
```text
检测到:本会话上下文已用 ~XX%(预计写下一章将消耗巨额 token)。

是否建议开启新会话?
- 同意:自动落盘断点,给出"新会话输入:续写《书名》"。
- 继续:本章照写,但提醒"写完这章建议结束会话"。
```

## 落盘断点(同意后自动做)
1. **全部数据落盘**:正文(manuscripts/)+ 分层摘要(更新当前章 L1/L2)+ 正典账本 + lessons + 面板刷新。
2. **写断点标记**:`<项目目录>/checkpoint.md`:
   ```markdown
   # 断点
   - 上次写到: 第 87 章
   - 下一章: 第 88 章(目标: 卷2高潮铺垫)
   - 下一章注入: L5 + 卷2L4 + 弧L3 + 区块L2 + 最近3条lessons
   - 会话继续输入: 续写《书名》
   ```
3. **更新记忆(仅稳定事实)**:`active-novel-project` 记忆**只更新稳定事实**(书名/路径/方向/约束),**不写"上次写到的章节"**——章节级进度写断点标记(checkpoint.md)+ 交接摘要进度节即可,记忆快照存进度必然滞后(2026-08-04 教训,详见 `write-novel/references/session-handoff.md` 铁律二)。
4. **给出指引**:新会话输入"续写《书名》"即可自动装配续接。

## 新会话自动续(已内建)
- 新会话说"续写《书名》"→ 读 `active-novel-project` 记忆(稳定事实)+ **读 checkpoint.md(上次写到/下一章)** + 列 drafts/ 实际文件 → 自动装配断点状态 → 无缝续写。**进度以 checkpoint.md + drafts/ 为准,不是记忆。**

## 防频繁打断
- 阈值设置避免"每章都问";只在累计超过 70% 或写满 10-20 章才触发。
- 用户可设"预算上限"(如每会话最多写 15 章),到上限即提示。

## 与 volume-session-plan 衔接
- 每会话 10-20 章是经验值;预算守卫自动在阈值触发,无需手动记。

# 状态机联动(High State Machine Sync)

各状态机独立运行是"简陋"之处——白金作家是"弧光/伏笔/战力/打脸三位一体咬合":**人物变化本身就是剧情引擎**。本文件补上联动规则。

## 四个状态机 + 联动关系
| 状态机 | 位置 | 独立运行(简陋) | 联动运行(白金) |
|--------|------|---------------|---------------|
| **角色弧光** | build-world 角色卡成长 | 只记录成长阶段 | 成长是剧情引擎,驱动后续事件 |
| **伏笔** | foreshadowing.jsonl | 只追踪开启/回收 | 伏笔回收=弧光突破的契机 |
| **战力** | power-system.md | 只防崩坏 | 战力晋级=弧光外化的结果 |
| **打脸/爽点** | plan-plot 爽点循环 | 只管爽点节奏 | 打脸=弧光+战力+伏笔的合力兑现 |

## 三位一体咬合规则(联动触发)
1. **弧光 → 战力**:角色内心突破(错误信念被打破)→ 战力晋级(外化)。**没有弧光的晋级 = 空洞升级**。
2. **伏笔 → 弧光**:关键伏笔回收 → 角色真相揭露 → 弧光推进。**伏笔兑现要落在角色变化上,不只落在情节**。
3. **战力 → 打脸**:战力晋级后安排打脸(兑现期待)。**打脸是弧光+战力+伏笔的合力,不是单独爽**。
4. **打脸 → 弧光**:打脸成功 → 角色获得成长反馈 → 推进弧光下一阶段。

## 检查(质量门联动检查)
每章后检查四个状态机的**联动一致性**:
- 战力晋级了,角色**内心**有对应变化吗?(无 → 空洞升级)
- 伏笔回收了,角色**弧光**推进了吗?(无 → 情节性回收,浪费伏笔)
- 打脸爽了,是**合力**兑现吗?(还是单独爽 → 降级为工业爽点)
- 弧光变了,伏笔/战力/打脸**响应**了吗?(无 → 弧光孤立)

## 状态机联动示例
```
第30章: 伏笔回收(身世真相)→ 弧光推进(错误信念动摇)
        → 战力晋级(心结解开,突破)→ 打脸(兑现期待,碾压宿敌)
        → 弧光再推进(放下执念)→ 新伏笔埋设(下阶段)
```

## 使用
- 写关键章(晋级/回收/打脸)前:检查四状态机是否**对齐触发**。
- 只动一个状态机、其他不动 → 告警"联动缺失",补对齐。

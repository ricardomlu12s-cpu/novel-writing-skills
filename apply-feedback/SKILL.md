# Reader Feedback — 读者意见受控微调

读者看到某章给意见,但**全书大纲已定**,要改但不能大动干戈。核心理念:**先分级,再最小化**——能改局部绝不动设定,能补衔接绝不动大纲。

## 0. 项目激活
- 先确认在哪个项目:读 `active-novel-project` 记忆 / `<项目目录>/ACTIVE`。
- 无激活项目则提示先开书。

## 1. 意见三级分级(Triage)
对每条读者意见分级(完整判定规则见 `references/triage-matrix.md`):
| 级 | 意见类型 | 处置 | 影响面 |
|----|---------|------|--------|
| **A 章内微调** | 措辞/节奏/细节描写 | 改该章局部,不动大纲 | 仅本章,零级联 |
| **B 章级微调** | 本章情节小调整 | 改本章,可能补一句衔接 | 本章+相邻,小级联 |
| **C 受控调整** | 涉及人物/伏笔/战力/后续走向 | 评估影响面→最小改动→级联更新 | 须最小化 |

分级判定优先级:**先看是否涉及"已登记的关键实体"(伏笔/承诺/战力/关系网)**——涉及即 C;不涉及则按"影响范围"分 A/B。

## 2. 微调落地
- **A 类**:直接改该章局部文本 → remove-ai-tone 去AI味 → 质量门 → 定稿。
- **B 类**:改本章 + 补一句衔接(引上章/承下章)→ 更新本章 L1 摘要 → 定稿。
- **C 类**:走级联最小化(下节)。
- **精准定位**(所有类通用):意见 → 定位到具体段落/句子(关键词/行号/语义锚)→ 精准替换,其他段落不动。完整方案见 `references/precise-edit.md`。改前先展示原文片段+拟改,确认后才动。
- **强制接续写**(软质量最终检验):读者反馈**必须**接续到下一章——
  - 处理完意见后,把"本批读者反馈摘要(分级/处置/教训)"写入 `lessons.md`(飞轮)或 `feedback-log.md`。
  - **写下一章时强制装配**最近一批读者反馈(不是可选项)。
  - 节奏/共鸣这类软质量,读者反馈是**最终检验**——比模型自检更真实。

## 3. 级联最小化(C 类核心)
完整方案见 `references/minimal-cascade.md`。步骤:
1. **评估影响面**:该改动触及哪些伏笔/承诺/战力/关系网/摘要(查 foreshadowing/promises/power-system/relationships.jsonl)。
2. **最小改动方案**:优先改"当前表达"而非"推翻设定";能用补一句衔接解决的,不改设定。
3. **级联更新**:确实要改设定的,按最小影响顺序更新:受影响章节正文 → 伏笔/承诺账本 → 分层摘要(仅相关层)→ 硬约束 prompt。
4. **铁律**:主线大纲架构(plan.md 顶层)**不因单条读者意见改动**;除非多意见叠加且用户明确确认。

## 4. 与质量链衔接
- 改后必过:remove-ai-tone(去AI味)+ plan-plot(一致性/套路)+ write-chapter 质量门。
- 刷新创作数据面板(render_panel)。
- 记入 `apply-feedback-log.md`(意见 → 处置 → 结果,供复盘)。

## 喂给谁 / handoff
- **write-chapter**:A/B 改章走其流水线;C 类级联更新走其账本/摘要。
- **remove-ai-tone**:改后必去AI味。
- **plan-plot**:C 类影响面涉及伏笔/战力时协同。
- **evolve-style**:C 级意见 ≥3 条指向同一维度 → 喂 cadence 中学习信号(见其维度三信号表)。
- **write-novel**:路由入口。
- 产物:`<项目目录>/apply-feedback-log.md`。

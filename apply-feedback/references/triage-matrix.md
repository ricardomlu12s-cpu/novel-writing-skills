# 意见三级分类矩阵(Triage Matrix)

判定一条读者意见该走 A/B/C 哪一级。

## 判定优先级
1. **先查关键实体**:该意见是否涉及**已登记的关键实体**(伏笔 foreshadowing / 承诺 promises / 战力 power-system / 关系网 relationships / 角色四维卡)?涉及 → **C 类受控调整**。
2. 不涉及关键实体 → 按"影响范围"分:
   - 仅本章局部(措辞/节奏/细节)→ **A**。
   - 影响本章情节小调整(事件处理)→ **B**。

## 分类矩阵
| 意见示例 | 级 | 理由 |
|---------|----|------|
| "这段打斗写得干瘪,重写一下" | A | 章内措辞/细节 |
| "这章节奏太拖,压缩一下" | A | 章内节奏 |
| "这个配角出场太突兀,加句铺垫" | B | 本章情节小调整+补衔接 |
| "反派突然变蠢了,不符合前面智商" | B | 本章处理欠佳(不涉关键实体) |
| "主角的金手指副作用之前没提,不合理" | C | 涉及金手指(战力/设定) |
| "这个伏笔埋了20章没回收,建议提前" | C | 涉及伏笔 |
| "两个角色的关系转折太突然,缺铺垫" | C | 涉及关系网 |
| "主角的成长太快,境界跳得没道理" | C | 涉及战力/成长 |

## 处置对照
| 级 | 处置 | 触碰文件 |
|----|------|---------|
| A | 改本章局部 | manuscripts/ch###.md |
| B | 改本章+补衔接+更L1摘要 | manuscripts/ + summaries/L1/ |
| C | 影响面评估→最小改动→级联 | 账本/摘要/硬约束(见 minimal-cascade.md) |

## 铁律
- **A/B 类绝不触碰 plan.md 大纲顶层**。
- **C 类单条意见不改主线架构**;多意见叠加且用户确认才动。
- 分级可用确定性规则先判(扫意见文本是否含关键实体名),LLM 兜底判复杂意见 → 省 token。

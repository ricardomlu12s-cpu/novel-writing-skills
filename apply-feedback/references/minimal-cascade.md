# 级联最小化方案(Minimal Cascade)

C 类意见的落地:改一处,影响最小,级联可追踪。

## 步骤

### 1. 评估影响面
查该改动触及哪些已登记实体:
```bash
# 搜意见关键词在账本中的命中
/usr/bin/grep -n "<关键词>" <项目目录>/canon-ledger/facts.jsonl
/usr/bin/grep -n "<关键词>" <项目目录>/foreshadowing.jsonl
/usr/bin/grep -n "<关键词>" <项目目录>/relationships.jsonl
```
产出**影响面清单**:受影响的章节 / 伏笔 / 承诺 / 战力 / 关系 / 摘要层。

### 2. 最小改动方案(优先级递减)
| 优先级 | 方案 | 何时用 |
|--------|------|--------|
| 1 | **改当前表达** | 改措辞/补一句即可,不动设定 |
| 2 | **补衔接/加过渡** | 意见是"突兀/缺铺垫",补一句衔接 |
| 3 | **登记新信息** | 意见是"之前没提",补登记到账本(非推翻) |
| 4 | **修订局部设定** | 设定确实矛盾,最小修订(只改该条) |
| 5 | **推倒重来** | 仅在多意见叠加+用户确认,且无更小方案 |

### 3. 级联更新顺序(最小影响)
```
受影响章节正文(manuscripts/)
  → 伏笔/承诺账本(foreshadowing/promises) — 若改动涉及
  → 分层摘要(仅相关层 L1/L2) — 正文变了摘要要同步
  → 硬约束 prompt(hard-constraint) — 若设定变了
  → relationships.jsonl — 若关系变了
```
> 每步只更新"受影响条目",不整卷重写。只追加/修订受影响行,不动无关行。

### 4. 回读确认
- 改后用 RAG 回读相关原文(`rag-recall.md`),确认级联无新矛盾。

## 铁律
1. **主线大纲架构(plan.md 顶层)不因单条意见改**。
2. **能改表达绝不动设定,能补衔接绝不动大纲**。
3. 每次级联记入 `apply-feedback-log.md`(改了什么/动了哪些账本/为什么),可回溯。

## 防"大动干戈"
- 意见若本质是"推翻核心设定/重写主线"→ 标 C-重,提示用户"这需要动大纲,建议单独评估",不自动执行。

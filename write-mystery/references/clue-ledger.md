# 线索账本(Clue Ledger)

每条线索的**公开程度**极讲究:谁看到了、什么时候公开、是否撒谎。可复盘的基础。

## 线索状态机
```
隐藏 ──→ 部分公开 ──→ 已公开
        (被某人看到)  (完全揭露)
```

## 线索条目 schema
```json
{
  "id": "c001",
  "desc": "管家袖口的血渍",
  "status": "部分公开",
  "seen_by": ["主角"],
  "revealed_ch": 3,
  "full_reveal_ch": null,
  "is_red_herring": false,
  "note": "血迹干涸时间与案发时间吻合"
}
```

## 公开程度讲究
| 程度 | 谁看到 | 效果 |
|------|--------|------|
| **隐藏** | 无人 | 待揭晓的秘密 |
| **部分公开** | 部分角色(主角看到,读者看到) | **最佳设计**:读者与主角信息同步,利用信息差 |
| **已公开** | 所有人 | 完全揭露 |

- **关键线索的"部分公开"**是智斗核心:读者看到一半,主角利用另一半(信息差)。
- **伪线索(red herring)**:明确标记,防读者误会为漏洞。

## 与伏笔联动
- 线索 = 伏笔的**具体化**(伏笔是叙事层,线索是智斗层)。
- 线索账本与 `foreshadowing.jsonl` 联动:伏笔回收时,对应线索应已公开。

## 脚本
```bash
python3 ~/.claude/skills/write-mystery/scripts/clue_ledger.py <项目目录> --report
```
- 登记/更新线索状态。
- 产出复盘报告:哪些线索何时公开、谁看到、有无"关键线索从未公开"(公平竞赛告警)。

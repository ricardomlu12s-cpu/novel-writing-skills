# 公平竞赛检查(Fair Play Check)

智斗的底线:**读者回头看,所有关键线索都公开过(或明确隐藏过且交代)**。防主角开天眼、防作者硬推。

## 复盘三查
| 查 | 问 | 不过 |
|----|-----|------|
| **线索公开过吗** | 每个关键线索在某个章节**公开过**(至少部分公开且读者可见) | 从未公开 = 开天眼 |
| **隐藏有交代吗** | 明确隐藏的线索,隐藏本身有伏笔/交代(不是作者藏了不说) | 无交代 = 作者硬藏 |
| **推理链完整吗** | 每条结论能由已公开线索推出 | 断链 = 硬推 |

## 复盘流程(智斗弧结尾)
1. **列关键线索**:本弧所有关键线索(从 clue-ledger.jsonl 取)。
2. **核对公开性**:每条 → 是否公开过(章节)/ 谁看到 / 是否伪线索。
3. **核对推理链**:每个"反转结论" → 能否由已公开线索推出(推理链检查)。
4. **出报告**:
```markdown
# 公平竞赛复盘
✅ 线索 c001(血渍):第3章部分公开(主角看到)→ 推理链完整
⚠️ 线索 c007(遗书):从未公开 → 主角却据此推断 = 开天眼,需补公开
✅ 伪线索 c003(指印):明确标记 red herring → 误导有效且公平
```

## 防开天眼铁律
- 主角的每个关键推断,必须**当时可见线索**支撑。
- 作者视角的信息**不得**通过主角之口说出(除非有交代:如主角事后才得知)。
- 读者能复盘的智斗 = 真智斗;复盘不了的 = 作者作弊。

## 与现有衔接
- 线索账本(clue-ledger)提供公开记录 → 复盘数据源。
- 推理链(reasoning-chain)提供结论回溯 → 复盘验证。
- 伏笔三级递现(foreshadowing-three-tier):伏笔兑现时,对应线索应已公开。

## 使用
```bash
# 结尾复盘: 公开性核对 + 关键线索未公开告警
python3 ~/.claude/skills/write-mystery/scripts/clue_ledger.py <项目目录> --fair-play

# 事前可解性 + 可信度三态(补"复盘"的事前维度):
# 解谜章 N 时,读者是否已拿到足够线索? confirmed 结论是否依赖 suspected 线索?
python3 ~/.claude/skills/write-mystery/scripts/solvability_check.py <项目目录> --solve-ch 45
```
输出公平竞赛报告(公开性核对 + 推理链验证 + 可解性评分 + 可信度三态)。

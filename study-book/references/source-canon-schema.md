# 源作设定库 Schema(Source Canon)

本文件定义 `<项目目录>/source-canon/` 下每个产物的精确格式。**对齐现链已建立的 schema**,不另造格式——这样连续性校验、面板渲染、RAG 回读都能直接消费。

## 兼容原则

| 现链已有 | 本引擎产出 | 对齐方式 |
|---|---|---|
| build-world `foreshadowing.jsonl` | source-canon `foreshadowing.jsonl` | 同格式,状态扩展为「已回收/未填」 |
| write-chapter `canon-ledger/facts.jsonl` | source-canon `facts.jsonl` | 同格式(含 known_by + ref) |
| write-mystery `clue-ledger` | source-canon `secrets.jsonl` | 同思路(seen_by/revealed_ch/is_red_herring) |
| write-chapter `timeline.md` | source-canon `timeline.md` | 同风格,每条标注 src_ch |
| build-world `characters/*.md` | source-canon `characters/*.md` | 同卡结构 + 源作 OOC 红线区 |

## canon.md — 原作快照

```markdown
# 源作快照: <作品名>

## 元信息
- 作者 / 连载状态 / 总章数 / 核心题材
- 输入文本: <路径> / 源作章节数 <N>

## 世界观骨架(L6, L1 公理层)
- 公理1: <世界的底层规则,永不漂移>
- 公理2: ...
- 力量体系: <等级/规则,若适用>
- 势力格局: <阵营/组织/地理>
- 历史脉络: <关键历史事件/世代因果>

## 世界框架守恒层级(最高铁律)
> **蝴蝶效应再大,人物/剧情可以改变,世界背景框架必须守恒。** 这是比"角色不OOC"更硬的一层约束。
- **S级·绝对公理(不可穿透)**: <世界最底层规则,如 人死不能复生(若原作如此)、世界的基本法则。任何蝴蝶效应/融入元素都不可改变。违反 = 破坏世界背景框架。>
- **A级·硬框架(改动需登记)**: <力量体系/势力格局/地理/时代。可因蝴蝶效应调整,但必须沿因果链重排、显式登记、不能与 S 级矛盾。>
- **B级·弹性(可合理演化)**: <设定细节/组织内部结构/次要背景。可随剧情合理演化,不得脱离世界内在逻辑。>

## 世界框架守恒检查
- 融入元素 <体系X> 属 <S/A/B 哪级>?
- 若要改变 <框架要素Y>: <Y 属 S(不可改) / A(需登记+重排) / B(可演化但守逻辑)>
- 因果链: 改变 <Y> 的下游 <事件Z> 重排了吗?(未触及的因果线忠于原作)

## 标志性细节(L1)
- 道具: <玉佩|信物|武器> — <出现章> <含义>
- 场景: <标志性地点> — <视觉细节>
- 行为指纹: <角色X> 常 <标志性动作/习惯>

## 时间线特殊结构(L4)
- 叙述序 vs 因果序: <正叙/倒叙/插叙/多线,标注差异>
```

> **守恒三问**(每融入一个新元素/大改剧情前,先问三遍):
> 1. 它触及世界框架吗?触及哪一级?(S/A/B)
> 2. 若触及 S 级 → **不可改**;A 级 → 登记 + 沿因果链重排;B 级 → 可演化但守逻辑。
> 3. 世界内在逻辑自洽吗?世界观是否仍是"原作的这个世界"?

## characters/<角色名>.md — 源作角色卡(L5)

**核心设计(满足三条铁律):**
1. **固定角色不能 OOC** → 分类标记 + 硬红线区(强约束)。
2. **蝴蝶效应可改变部分角色** → 源作基线 vs 同人演化双轨 + 演化合理性门槛。
3. **不压缩人物形象** → 反压缩区保留立体性(内在矛盾/未被展开侧面/成长开放性)。

```markdown
# 源作角色: <名>

## 分类标记
- 角色类别: <固定角色 | 可变角色 | 混合>
  - **固定角色**: 形象必须忠于原作,红线绝不可越(同人稳定锚)。
  - **可变角色**: 会因同人融入因素产生蝴蝶效应,形象/结局可演化(但要合理性)。
  - **混合**: 部分特质固定、部分可演化(如 性格固定,经历可变)。
- 守卫强度: <强约束(硬红线) | 弹性约束(允许合理演化)>
- 固定面: <若混合,列哪些特质固定>

## 本源
- 身份 / 年龄 / 外貌 / 性格(三句内,写立体而非单标签)
- 核心欲望: <行为内部驱动>

## 反压缩区(立体性保留,防"形象压缩")
- 内在矛盾/张力: <人设中自相矛盾的两面,如 冷酷×护短、理智×冲动——不是单一标签>
- 未被原作展开的侧面: <原作一笔带过、同人可深挖的潜能>
- 成长开放性: <弧线不是终局,可延展的方向(写死会压缩形象)>

## 行为边界
- 会做: <符合人设的行为模式>
- 绝不做(OOC 硬红线): <① 绝不会背叛同伴 ② 绝不用下作手段 ③ ...>
- 可演化(蝴蝶效应区): <若融入因素,哪些行为/边界可松动,怎么松动才不崩人设>

## 源作基线 vs 同人演化(双轨)
- 源作基线: <原作中的形象 / 结局(第X章)>
- 同人演化轨: <因蝴蝶效应导致的形象/结果变化 —— Phase 3 填写,本阶段留空>
- 演化合理性: <变化必须有因果动机(蝴蝶效应的因果链),不能无缘无故改人设>

## 声线
- 口头禅 / 句式 / 词汇域 / 回避话题

## 知识边界(POV)
- 知道: <秘密A、秘密B>
- 不知道: <秘密C>

## 角色弧(原作)
- <阶段1> → <阶段2> → ... (原作的成长轨迹)

## 刻画手法参考
- <来自 learn-style 风格指纹:这个角色用哪种手法立人>
```

> - **OOC 硬红线区**是 Phase 3 守卫的基准:**固定角色这些红线绝不能越**。
> - **可演化区 + 双轨**是蝴蝶效应的管理闸门:可变角色可以变,但变必须有因果动机、有合理性,并且**记录在双轨里**,防止"为了剧情强行改人设"。
> - **反压缩区**防"形象压缩":角色卡若只剩三句单标签性格,就是把人写扁了——反压缩区强制保留矛盾面、未展开侧面、成长开放。

## foreshadowing.jsonl — 伏笔全景(L2)

```json
{"id":"f001","desc":"主角身世的玉佩","opened_ch":12,"status":"已回收","payoff_ch":45,"payoff_note":"玉佩是母亲遗物,揭开身世"}
{"id":"f002","desc":"神秘人警告","opened_ch":20,"status":"未填","payoff_ch":null,"payoff_note":"到全书完结未回收,可续写"}
```

- 状态机:`已回收`(作者已填)/ `未填`(作者留下的坑,同人可续)。
- 与 build-world 格式兼容(它在 `开启→悬置→回收` 间流转;本引擎读原作,直接标终态「已回收/未填」)。
- `payoff_note` 记录回收方式,供同人借鉴"作者怎么收"。

## secrets.jsonl — 隐藏信息(L3)

```json
{"id":"s001","secret":"主角真实身份是皇族遗孤","seen_by":["主角","读者"],"revealed_ch":88,"is_red_herring":false}
{"id":"s002","secret":"老管家是反派卧底","seen_by":["反派"],"revealed_ch":null,"is_red_herring":true}
```

- `seen_by`:谁知道这个秘密(角色+读者)。`revealed_ch: null` = 全书未揭示。
- `is_red_herring`:是否误导(作者故意放的假线索)。与 write-mystery 线索账本同思路。

## timeline.md — 因果时序重建(L4)

```markdown
# 时间线(按因果时序,标注源作章节)

## 因果序 1(叙述章 3,倒叙)
- <事件> — 发生于 <时间/因果节点>
## 因果序 2(叙述章 1,正叙)
- <事件>
```

- **按因果时序排**,不是按原叙述序。每条标注源作章节 + 叙述序/因果序差异。
- 这是 Phase 2 重排的前提。

## causality.md — 因果链(L7,蝴蝶效应的锚点)

```markdown
# 因果链(事件因果图)

## 因果: <事件A> → <事件B>
- 原因: <A 为什么导致 B>
- 源作章节: A@12, B@20
- 关键分岔: <是否改变剧情走向>

## 迟到原因
- <作者为悬念而隐藏的因果>: <事件C 的真正原因在第88章才揭示>

## 蝴蝶效应锚点(同人核心)
- <源作事件X> 是**锚点**:同人一旦改变它,后续因果线会连锁。
  - 下游受牵事件: <事件Y、事件Z>(原作中由 X 导致的)
  - 改变 X 的后果: <Y/Z 会如何变,必须沿因果链推演,不能跳因果>
  - 因果链校验: 改变 X 后,Y 的旧因果还成立吗?不成立 → 必须重排其下游。

## 因果链规则(防脱缰)
1. 蝴蝶效应**必须挂在锚点上**:每次融入因素都要明确"改变了哪个源作事件"。
2. **改锚点必须重排下游**:不能只改事件结果、不改其因果链,否则因果断裂。
3. **未触及的因果线保持原样**:同人没动的源作因果,必须忠于原作。
4. 每条蝴蝶效应记录"源头变更 → 连锁重排"的完整链条,供连续性校验。
```

- 这是 Phase 2「打乱重排」的输入:因果链决定"哪些事件必须保持先后,哪些可重排"。
- 蝴蝶效应区是 Phase 4 融合的锚点:融入体系 → 改锚点 → 沿因果链重排下游。

## butterfly-ledger.jsonl — 蝴蝶效应账本(同人写作核心追踪)

**为什么必须有这个账本**:L7 锚点/角色双轨/因果链规则定义了"应该怎么守",但写 100 章同人时靠记忆守不住因果线。账本逐条追踪每条蝴蝶效应,防"因果脱缰"。**写作过程中不断追加,不是拆书一次性产物。**

```json
{"id":"b001","src_event":"源作第12章:主角得知玉佩来历","change":"同人第3章:让主角提前发现玉佩的秘密","triggered_ch":"同人3","affected_causality":["c002","c005"],"affected_chars":["主角","老管家"],"status":"已重排","payoff_ch":"同人58","note":"玉佩提前揭开→老管家后续背叛提前至同人20章"}
{"id":"b002","src_event":"源作第40章:宗门大战","change":"融合《XX》力量体系后宗门大战规模扩大","triggered_ch":"同人15","affected_causality":["c010"],"affected_chars":["女二"],"status":"已登记未重排","payoff_ch":null,"note":"下游事件Z尚未重排,需沿因果链推演"}
```

字段:
- `src_event`:源作被改变的事件(锚点)。
- `change`:同人的改变(怎么改的)。
- `triggered_ch`:改变触发的**同人**章节。
- `affected_causality`:受影响的下游因果链 ID(对应 causality.md)。
- `affected_chars`:受影响角色。
- `status`:状态机 `已登记 → 已重排 → 已兑现 / 待重排`。
- `payoff_ch`:兑现章(下游事件重排后落在哪章)。
- `note`:推演备注(因果链怎么重排的)。

**账本规则(防因果脱缰):**
1. **每次融入因素/改剧情 → 先登记**:改了源作哪个事件(锚点)。
2. **必须沿因果链重排下游**:`affected_causality` 列出的下游事件,逐个重排;不能只改结果不排因果。
3. **未触及的因果线保持原样**:账本之外 = 忠于原作,不许悄悄改动。
4. **状态机推进**:登记 → 重排(下游因果连好) → 兑现(同人写到 payoff 章)。任何"待重排"悬置超过一定章数 → 告警(防脱缰)。
5. **连续校验**:同人写每章时,连续性引擎检查"本章是否牵涉某条未重排的蝴蝶效应"。

## 世界框架守恒 + 蝴蝶效应账本联动

- 每次登记蝴蝶效应,先过**守恒三问**(见 canon.md):触及世界框架 S/A/B 哪级?
  - S 级 → **不可登记**,改到未触及 S 级为止(或重设计融入元素)。
  - A 级 → 登记 + 沿因果链重排 + 显式标注。
  - B 级 → 可登记,但守世界内在逻辑。

## merge-registry.jsonl — 多书融合注册表(Phase 3)

**多本书合并时**:一本书作**主体(主书)**,其他书作**改版的人物形象或情节因素**(调味)。本注册表记录"从哪本书借了什么、挂在哪",防缝合怪 + 防跨书 OOC。

```json
{"id":"m001","book":"《主书》","role":"主书(主体底盘)","borrowed":["世界观框架","主角本源","力量体系"],"inject_as":["世界骨架","主角(固定角色)","力量体系(外来体系)"],"priority":1,"conflict_rule":"主书优先","butterfly_cross_book":["b002"],"note":"主角以主书《主书》为准"}
{"id":"m002","book":"《辅助书》","role":"辅助书(调味)","borrowed":["配角人设作为配角改版","道具元素"],"inject_as":["配角(改版形象)","道具(外来元素)"],"priority":2,"conflict_rule":"与主书冲突时让位于主书","butterfly_cross_book":["b005"],"note":"改版配角借用辅助书的人物形象内核,但服从主书世界框架"}
```

字段:
- `book`:来源书。
- `role`:主书(主体底盘)/ 辅助书(调味)。
- `borrowed`:从这本书借了什么。
- `inject_as`:融入同人后变成什么(哪个角色/体系/元素)。
- `priority`:主书 1,辅助 2+。
- `conflict_rule`:**跨书角色 OOC 冲突时以主书优先**(核心规则)。
- `butterfly_cross_book`:该借入元素引发的跨书蝴蝶效应(对应 butterfly-ledger)。
- `note`:备注。

**跨书 OOC 优先级(核心):**
1. **主书角色 = 最硬基准**:同人中的角色若源于主书,以主书人设为准,其他书借来的只能"借鉴",不能覆盖主书角色本源。
2. **辅助书角色 = 可改版**:辅助书借入的角色形象可改版(融入同人),但改版后仍是"主书世界里的角色",须服从主书世界框架守恒级。
3. **借入元素不穿越框架**:辅助书的体系/元素注入时,同样过守恒三问(S/A/B),不与主书 S 级公理冲突。

## external-axioms.jsonl — 外来公理登记(Phase 4 体系磨合)

**引入体系与原世界观差距大时**,不能硬塞。每个外来公理显式登记,标其挂在主书世界框架哪一级 + 磨合方式。

```json
{"id":"e001","axiom":"《XX》修炼体系的'灵气吸收'规则","source_book":"《XX》","target_level":"A级硬框架","compat_with_s":"不冲突(灵气不违反主书人死不复生的绝对公理)","bridge":"以外来体系'补充'主书力量体系空缺,不覆盖","status":"已磨合","note":"灵气体系挂主书力量体系之下"}
{"id":"e002","axiom":"'死后世界轮回'设定","source_book":"《YY》","target_level":"S级绝对公理","compat_with_s":"冲突!主书为'人死不能复生'","bridge":"需改造:改为'残念存留'而非复活","status":"待磨合","note":"不能直接注入,否则破坏主书世界背景框架"}
```

字段:
- `axiom`:外来公理。
- `source_book`:来源书。
- `target_level`:挂主书框架哪一级(S/A/B)。
- `compat_with_s`:与主书 S 级绝对公理是否冲突。
- `bridge`:磨合桥梁(怎么接入而不打碎原世界)。
- `status`:`待磨合 → 已磨合 / 已拒绝`。
- `note`:备注。

**磨合规则:**
1. **先过守恒三问**:外来公理触及主书框架哪级?
2. **与 S 级绝对公理冲突 → 必须改造或拒绝**:不能直接注入破坏世界背景框架。

# 多书融合协议(Fusion Protocol)

同人文常有多本书合并:**一本书作主体,其他书作改版的人物形象或情节因素**。融合不好 → 缝合怪;角色借用不好 → 跨书 OOC。本协议定义怎么融合、怎么守。

## 核心:主从底盘(复用 anti-sewing-merge)

多书融合沿用现链 `anti-sewing-merge.md` 三机制,落地到同人场景:

| 机制 | 落地 |
|---|---|
| **主从底盘** | 定**一本主书**作世界框架+核心角色底盘,其他书只做**调味**(借角色/借元素) |
| **冲突消解** | 主书 vs 辅助书冲突 → **主书优先**(尤其角色 OOC) |
| **内核优先** | 借"为什么好看"(角色内核/情感张力),不借表皮台词 |

## 步骤

1. **定主书**:哪本书提供世界框架 + 核心角色?(如《龙族》作底盘)
2. **定辅助书 + 借什么**:
   - 辅助书A:借 `魏无羡` 人设 → 作配角(改版形象)
   - 辅助书B:借 `阴虎符` 元素 → 作道具(外来元素)
3. **登记**:写进 `merge-registry.jsonl`(从哪借、挂在哪、优先级、冲突规则、跨书蝴蝶)。
4. **跨书 OOC 检查**:借入角色/元素,与主书角色本源比对,冲突以主书为准。
5. **蝴蝶效应跨书记账**:借入元素引发的蝴蝶效应,进 `butterfly-ledger.jsonl` 并标 `merge-registry` 关联。

## 跨书 OOC 优先级(三条铁律)

1. **主书角色 = 最硬基准**:同人角色若源于主书,以主书人设为准。辅助书借来的只能"借鉴",不能覆盖主书角色本源。
2. **辅助书角色 = 可改版**:辅助书借入角色可改版,但改版后仍是"主书世界里的角色",须服从主书世界框架守恒级。
3. **借入元素不穿越框架**:辅助书体系/元素注入时,同样过守恒三问(S/A/B),不与主书 S 级公理冲突。

## 防缝合检测(融合后)

沿用 anti-sewing-merge 检测,加同人维度:
1. **主从分明**:有明确主书底盘吗?(不是并列堆叠)
2. **跨书不 OOC**:借入角色服从主书基准了吗?
3. **世界框架守恒**:辅助书元素穿越主书 S 级公理了吗?
4. **自洽感**:去掉来源标签,是一部主书世界里的自洽作品吗?

## 与蝴蝶效应账本联动

- 每次借入辅助书元素 → 视为一次"融入因素" → 触发蝴蝶效应登记(改哪个锚点)。
- 跨书蝴蝶效应在 `butterfly-ledger` 里标 `merge-registry` 来源,追踪其跨书传播。
- 借入元素引发的下游重排,同样沿因果链,不能跳因果。

## 产物

- `merge-registry.jsonl`(融合注册表,见 source-canon-schema.md)。
- 每次开融合同人书时生成;写作中可追加借入。

# Book Deconstruction — 拆书引擎

深度解构一部作品的**入口**(通用,原创/同人都可用)。把原作当**完整矿藏**开采,产出**源作设定库(source-canon)**。

> **核心:先按"用途 + 改变强度"决定拆多深、守多严**,不是"同人一律全拆守恒"。
> - **原创借鉴**:作者想深度学某作品的文风/结构/伏笔/世界观骨架 → 拆书作**学习参考**,不强制守恒、不设 OOC 红线。只想学文风指纹,则 learn-style 就够,不必拆书。
> - **同人**:按四档细分(见下),每档拆书深度、守恒强度都不同。
>
> **定位区分**:learn-style 吸收**手法**(怎么写,浅层);本引擎提取**内容忠实地基**(原作里到底有什么,七层深挖)。

## 同人四档细分(开书即定档,决定拆书与守恒强度)

| 档位 | 定位 | 改变什么 | 拆书 | 守恒强度 |
|---|---|---|---|---|
| **补白型** | 前传/后传/番外/配角视角 | 不碰原著已定事实,填空白 | 必拆全量 | **强守恒**:剧情严丝合缝,OOC 是死罪 |
| **改写型** | IF线/穿越(如"救回绘梨衣") | 改关键节点,下游重排 | 必拆全量 | **守恒世界观,剧情可改**:蝴蝶账本必须 |
| **架空型** | AU(现代校园/换职业) | 只借角色名/元素,剧情全新 | 可选浅拆 | **弱守恒**:仅元素不冲突,不要求还原 |
| **融合型** | 多书联动 | 多书合并 | 拆多本 | **主从底盘 + 跨书 OOC 守卫** |

- **补白型/改写型**才需要全量拆书 + source-canon 作基准线 + 蝴蝶账本。
- **架空型**只浅拆(借了哪些元素/角色内核),不要求还原原著剧情。
- **融合型**拆多本,主书作主体底盘,辅助书作调味(见 Phase3)。

## 核心理念

**原作 = 矿藏,不是范本。**
- 挖的是**细节/伏笔(已填+未填)/隐藏信息/时间线/角色本源/世界观骨架/因果链**七层。
- 产物是**结构化的、可复用的、永久生效**的设定库,不是读后感。
- 同人文的"世界真实感"来自对原作的**深度忠实** + 因果重排,而不是搬原文台词。

**最高铁律 — 世界框架守恒:**
> **蝴蝶效应再大,融入元素与原作差异再大,人物/剧情走向可以改变,但整体的故事世界背景框架必须保持符合原作。** 这是比"角色不OOC"更硬的一层约束。守恒层级见 L6(绝对公理不可穿透 / 硬框架改动需登记+重排 / 弹性可合理演化)。

## 七层拆解(L1-L7 矿藏)

| 层 | 挖什么 | 产物 | 服务后续 |
|---|---|---|---|
| L1 细节矿 | 关键道具/场景/习惯用语/标志性细节 | canon.md + facts.jsonl | 细节真实感 |
| L2 伏笔全景 | 全部伏笔,含**已填+未填**、回收章节 | foreshadowing.jsonl | 填坑/不崩 |
| L3 隐藏信息 | 秘密/误导/悬念,谁知道什么、何时揭示 | secrets.jsonl | 悬念设计 |
| L4 时间线 | 按**因果时序**重建事件流,标注源作章节 | timeline.md | 打乱重排前提 |
| L5 角色本源 | 本源身份/**分类(固定/可变)**/OOC硬红线/**可演化区**/**反压缩区**(防形象压缩)/源作基线+同人演化双轨 | characters/*.md | OOC 守卫 + 蝴蝶效应 |
| L6 世界观骨架 | L1 公理/**守恒层级**(S绝对公理不可穿透/A硬框架需登记/B弹性可演化) | canon.md | **世界背景框架守恒** |
| L7 因果链 | 事件因果图 + **蝴蝶效应锚点**(改锚点必须重排下游,未触及因果线忠于原作) | causality.md | 打乱重排输入 + 因果不脱缰 |

完整规范见 `references/deconstruction-layers.md`。
- **设定来源标签 + 大事件锚点状态机**(通用:原创/同人都用,追"这条设定从哪来、这个事件处于什么状态")见 `references/canon-tagging.md`。

## 产物存储(源作设定库)

```
<项目目录>/source-canon/        # 不可变基准线
├── canon.md            # 原作快照:元信息 + 世界观骨架
├── characters/         # 源作角色卡(每人一卡)
├── foreshadowing.jsonl # 伏笔全景(已回收/未填)
├── secrets.jsonl       # 隐藏信息/秘密
├── timeline.md         # 因果时序重建
├── facts.jsonl         # 原子事实(known_by + ref)
├── causality.md        # 因果链(含蝴蝶效应锚点)
├── butterfly-ledger.jsonl # 蝴蝶效应账本(写作中追加,追踪因果脱缰) ⭐
├── merge-registry.jsonl  # 多书融合注册表(Phase3:主书/辅助书/优先级/OOC冲突规则) ⭐
├── external-axioms.jsonl # 外来公理登记(Phase4:守恒三问/S级冲突/磨合桥梁) ⭐
├── chapter-map.md      # 源作章节→因果序映射(Phase2 重排用)
└── deconstruct-report.md # 拆书报告:未填坑清单/OOC红线/吸收与规避
```

schema 见 `references/source-canon-schema.md`。

## 执行协议(多轮,一次性成本、产物永久)

```
Pass 0 脚本定位   chapter_split.py 分章 + 每章字数/信号统计(免费)
Pass 1 分块提取   每 10-20 章一块,LLM 按结构化 schema 提取 → 块级 ledger(JSONL)
Pass 2 合并成典   块级 ledger → 去重合并 → 源作设定库(伏笔跨块配对 opened/payoff)
Pass 3 校验报告   矛盾扫描(死人复活/时间冲突/秘密泄露) + 未填坑清单 + OOC红线 → deconstruct-report
```

详见 `references/multi-pass-protocol.md`。
- **可续跑**:块级 ledger 落盘,中断断点续。
- **深度可配置**:`浅拆`(单遍线索)/ `深拆`(多轮全量,默认)。
- **成本模型**:一次性几万~几十万 token,产物永久复用;后续写章只注入源作设定库精华。

## 拆书路径(按档位决定拆多深、守多严)

```
原创(可选拆): study-book ──学习参考(不守恒)──▶ learn-style → build-world → write-chapter

同人(按四档): study-book ──▶ learn-style → build-world → write-chapter
  补白型 → 全量拆 + 强守恒(剧情严丝合缝,OOC 死罪)
  改写型 → 全量拆 + 守恒世界观(蝴蝶账本必须)
  架空型 → 浅拆(只借元素/内核,不还原剧情)
  融合型 → 拆多本 + 主从底盘(主书基准,辅助书调味)
```

- **同人按档定拆书深度**:补白型/改写型必全量拆;架空型只浅拆;融合型拆多本。
- **原创可选拆书**:想深度学一部作品(结构/伏笔/世界观骨架)→ 拆书作学习参考,不守恒;只想学文风 → learn-style 就够。
- **原创不拆书**:跳过本入口,直接 learn-style(或直接 build-world)。

## 边界

- 本阶段(Phase 1)只做**拆书**,不做重排/融合/体系磨合。
- **Phase 2 打乱重排**:用 L7 因果链 + chapter-map.md → 重排后大纲 → 正文由 write-chapter 全新撰写(不搬原文)。
- **Phase 3 多书融合 + OOC 守卫**:复用 anti-sewing-merge 主从底盘/冲突消解/内核优先;L5 角色本源卡 OOC 红线做守卫。落地 `merge-registry.jsonl`(主书/辅助书/优先级/冲突规则)+ 跨书蝴蝶效应记账。详见 `references/fusion-protocol.md`。
- **Phase 4 体系差异磨合**:L6 世界观骨架 L1 公理做冲突检查,引入体系需显式登记"外来公理"。落地 `external-axioms.jsonl`(守恒三问 + S级冲突改造/拒绝 + 磨合桥梁:补充/借位/改造)。详见 `references/system-integration-protocol.md`。
- **写作期核心(已就绪)**:`butterfly-ledger.jsonl` 逐条追踪蝴蝶效应(改锚点→重排下游→兑现),防因果脱缰;与守恒三问联动。

## 喂给谁 / handoff
- **learn-style**:角色本源卡 → 刻画手法参考。
- **build-world**:source-canon → 同人设定库的不可变底(同人新增元素在其上叠加)。
- **write-chapter**:source-canon 角色卡/伏笔/时间线注入 + 连续性校验基准。
- **write-novel**:同人文路由入口;产物为全链基准。

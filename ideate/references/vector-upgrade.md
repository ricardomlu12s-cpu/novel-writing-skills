# 向量检索升级(Vector Upgrade)

当概念库变大、或需要"语义相似但领域不同"的远邻时,纯图随机游走质量下降,换向量检索。

## 何时升级
- 概念库 > 1000 概念,或图结构复杂到随机游走找不到高质量远邻。
- 需要"语义远邻": 不是同领域,而是**语义上相关但跨领域**的概念(如"债务"语义接近"契约/负担/赎罪",跨越经济/法律/宗教)。

## 方案(从零成本到高成本)

### 1. 纯本地 TF-IDF(零依赖,当前够用)
- 用 `sklearn.feature_extraction.text.TfidfVectorizer`(或自实现)对概念库建向量。
- 找"与当前情节向量相似度中等(不是最高)的概念"= 远邻。
- 无需 embedding 模型,纯 CPU。

### 2. 本地 embedding 模型(中成本,推荐)
- `sentence-transformers` + 一个中文小模型(如 `shibing624/text2vec-base-chinese`)。
- 概念向量化后,用余弦相似度找"相似度 0.4-0.7"的中距离邻居(太近=老套,太远=无关)。
- 离线可用,不烧 API token。

### 3. 云 embedding API(高成本,已有 key 时)
- OpenAI/Anthropic embedding,概念库一次性向量化缓存,查询时才调。

## 与 MCP 的关系
- 若向量库要**跨会话常驻**(避免每次重载模型/重建索引),做成 MCP server:
  - 一个常驻进程持有向量索引,Claude 通过 MCP 工具 `concept_neighbor(query, k)` 调用。
  - 适合"多本书长期共用一个大概念库"的场景。
- 当前阶段(概念库小、单机、单人)文件 + 脚本足够,**先不上 MCP**。

## 判断标准(什么时候真的需要 MCP)
1. 需要**常驻进程**持有状态(向量索引/图数据库)跨会话复用。
2. 需要**外部服务**集成(联网查新概念/调用外部知识图谱)。
3. 多人协作(资产库要共享给团队)。

满足其一再上 MCP,否则 skill + 脚本更简单、更好维护。
